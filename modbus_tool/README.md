# Modbus RTU Tool

Дополнение Home Assistant: сканирование и настройка устройств Modbus RTU на шине RS485 через USB-адаптер. Всё делается из панели в боковом меню, консоль не нужна.

Версия 0.2.0.

## Установка

1. В Home Assistant откройте **Настройки → Дополнения → Магазин дополнений**.
2. Справа сверху нажмите **⋮ → Репозитории**.
3. Вставьте адрес репозитория и добавьте его:

   `https://github.com/Waitancheg/ha-modbus`

4. Обновите магазин, найдите **Modbus RTU Tool** и нажмите **Установить**. Сборка идёт на самом устройстве и занимает несколько минут.
5. Запустите дополнение. В боковом меню появится пункт **Modbus RTU**. Откройте его.
6. На главном экране выберите порт (`/dev/serial/by-id/…` или `/dev/ttyUSB…`), скорость, чётность, стоп-биты и имя хаба. Поля применяются сразу и запоминаются в `/data/settings.json`. Вкладка «Конфигурация» дополнения задаёт только начальные значения.

Если пункт не появился сразу, обновите страницу Home Assistant. Дополнение само при загрузке HA не стартует (`boot: manual`), чтобы не занимать порт, пока вы им не пользуетесь.

## Как пользоваться портом вместе с интеграцией modbus

Интеграция `modbus` и это дополнение не могут держать один и тот же последовательный порт одновременно.

Если имя хаба пустое, шина закрыта, пока не отметите **HA не использует этот порт**.

Если имя задано, перед каждой операцией вызывается `modbus.stop`, после неё — `modbus.reload` (службу `modbus.restart` убрали в Home Assistant 2024.11). Reload поднимает все хабы modbus.

**Освободить хаб** останавливает хаб и включает сессию: следующие операции больше не делают stop/reload, порт остаётся вашим. **Вернуть хаб** вызывает `modbus.reload` и снова включает автоматический режим.

Порт открывается только на время операции. Пока идёт скан, другие действия с шиной отклоняются.

## Главный экран

Сверху всегда видны порт и скан, не в отдельных вкладках:

- устройство из `/dev/serial/by-id/*` и `/dev/ttyUSB*` (остальные tty тоже в списке), скорость 1200…115200, чётность, стоп-биты, биты данных, таймаут, пауза кадра, повторы, порог эха, имя хаба и его состояние;
- скан: диапазон адресов 1…255 (255 входит), несколько скоростей, при необходимости другие варианты чётности, функции FC03/FC01/FC02 и кнопка **Стоп**. Скан только читает. Ответ-исключение означает «устройство есть».

Ниже:

- **Чтение** — FC01/02/03/04, таблица DEC / HEX / SIGNED / BIN.
- **Запись** — FC05 (ВКЛ = `0xFF00`, ВЫКЛ = `0x0000`), FC06, FC15, FC16. Кадр уходит только после **Подтвердить запись**.
- **HEX** — CRC16 по галочке. Чтение с адресом 1…255 уходит сразу. Запись и broadcast (адрес 0) сначала показывают кадр.
- **Журнал** — кадры TX/RX.
- **Профили** — готовые карты регистров и кнопки.
- **YAML** — по умолчанию только списки `sensors` / `switches` / `binary_sensors` для вставки в существующий хаб. Галочка добавляет полный блок `modbus:`. Для реле выбирается 2, 4 или 8 каналов.

Кнопка **В формы** у найденного адреса подставляет его в чтение, запись и YAML.

## Профили в комплекте

Описание регистров и ограничения — в [DOCS.md](DOCS.md).

- **Eletechsup N4DSA02** — два DS18B20. Регистры 0 и 1: температура int16 × 0.1 °C, `32768` = нет датчика. Регистр 2 — адрес, регистр 3 — код скорости (0=1200 … 4=19200), запись FC06. Новая скорость после цикла питания. Значение 5 в регистр скорости кнопки профиля не отправляют (заводской сброс). Регистр 255 — не скорость.
- **Реле 2CH/4CH (Bestep/LC)** — по умолчанию адрес 255, 9600 8N1. Катушки 0…7 через FC05, чтение реле FC01 и входов FC02 с количеством 8 (количество 4 на этих платах часто молчит). Адрес меняется broadcast-кадром FC16 на slave 0. Скорость — FC16, регистр `0x03E9`.
- **R4DCB08** — восемь температур, holding-регистры 0…7, int16 × 0.1 °C.

Свои профили кладутся YAML-файлом в каталог `profiles/` рядом с приложением (в образе это `/opt/modbus_tool/profiles`).
