# Modbus RTU Tool

Дополнение Home Assistant: сканирование и настройка устройств Modbus RTU на шине RS485 через USB-адаптер. Всё делается из панели в боковом меню, консоль не нужна.

Версия 0.1.0.

## Установка

1. В Home Assistant откройте **Настройки → Дополнения → Магазин дополнений**.
2. Справа сверху нажмите **⋮ → Репозитории**.
3. Вставьте адрес репозитория и добавьте его:

   `https://github.com/Waitancheg/ha-modbus`

4. Обновите магазин, найдите **Modbus RTU Tool** и нажмите **Установить**. Сборка идёт на самом устройстве и занимает несколько минут.
5. На вкладке **Конфигурация** укажите:
   - **Последовательный порт** — `/dev/ttyUSB0` или стабильный путь `/dev/serial/by-id/usb-…` (его видно в интерфейсе дополнения после запуска);
   - **Имя хаба Modbus** — значение `name` у вашего хаба в `configuration.yaml`. Если интеграция `modbus` этим портом не пользуется, оставьте имя пустым.
6. Запустите дополнение. В боковом меню появится пункт **Modbus RTU**. Откройте его.

Если пункт не появился сразу, обновите страницу Home Assistant. Дополнение само при загрузке HA не стартует (`boot: manual`), чтобы не занимать порт, пока вы им не пользуетесь.

## Как пользоваться портом вместе с интеграцией modbus

Интеграция `modbus` и это дополнение не могут держать один и тот же последовательный порт одновременно.

Если задано имя хаба и включено «Перед шиной вызывать modbus.stop», дополнение перед сканированием, чтением, записью и HEX-кадром вызывает службу `modbus.stop` с `{"hub": "<имя>"}`, а после операции — `modbus.restart`. Кнопки **Освободить хаб HA** и **Вернуть хаб HA** делают то же самое вручную.

Порт открывается только на время операции и затем закрывается.

В Home Assistant 2024.11 службу `modbus.restart` удалили. Если она отвечает ошибкой, дополнение вызывает `modbus.reload`. Эта служба перечитывает YAML и заново открывает **все** хабы modbus, не только указанный.

## Вкладки

- **Порт** — устройство, скорость 1200…115200, чётность, стоп-биты, таймаут ответа, пауза между кадрами, порог локального эха.
- **Скан** — диапазон адресов 1…255 (255 входит: заводской адрес многих китайских плат реле) и одна или несколько скоростей. Только чтение: FC03 регистр 0 количество 1, если тишина — FC01 количество 8, затем FC02 количество 8. Ответ-исключение Modbus означает «устройство есть». Во время скана на шину ничего не пишется.
- **Чтение** — FC01/02/03/04, таблица DEC / HEX / SIGNED / BIN.
- **Запись** — FC05 (ВКЛ = `0xFF00`, ВЫКЛ = `0x0000`), FC06, FC15, FC16. Сначала показывается кадр, на шину он уходит только после **Подтвердить запись**.
- **HEX** — произвольный кадр, CRC16 дописывается по галочке. Нужен для broadcast-адреса 0 и нестандартных плат.
- **Журнал** — кадры TX/RX.
- **Профили** — готовые карты регистров и кнопки.
- **YAML** — фрагмент `modbus:` (sensors / switches / binary_sensors) для `configuration.yaml`. Его нужно вставить вручную.

Кнопка **В формы** у найденного адреса подставляет его в чтение, запись и YAML.

## Профили в комплекте

Описание регистров и ограничения — в [DOCS.md](DOCS.md).

- **Eletechsup N4DSA02** — два DS18B20. Регистры 0 и 1: температура int16 × 0.1 °C, `32768` = нет датчика. Регистр 2 — адрес, регистр 3 — код скорости (0=1200 … 4=19200), запись FC06. Новая скорость после цикла питания. Значение 5 в регистр скорости кнопки профиля не отправляют (заводской сброс). Регистр 255 — не скорость.
- **Реле 2CH/4CH (Bestep/LC)** — по умолчанию адрес 255, 9600 8N1. Катушки 0…7 через FC05, чтение реле FC01 и входов FC02 с количеством 8 (количество 4 на этих платах часто молчит). Адрес меняется broadcast-кадром FC16 на slave 0. Скорость — FC16, регистр `0x03E9`.
- **R4DCB08** — восемь температур, holding-регистры 0…7, int16 × 0.1 °C.

Свои профили кладутся YAML-файлом в каталог `profiles/` рядом с приложением (в образе это `/opt/modbus_tool/profiles`).
