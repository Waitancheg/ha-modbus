# Modbus RTU Tool — устройство и ограничения

Дополнение для Home Assistant OS / Supervised. Веб-интерфейс доступен только через ingress (боковая панель). Слушает порт 8099 внутри контейнера и принимает соединения от Supervisor (`172.30.32.2`) и с localhost.

## Доступ к адаптеру

В `config.yaml` включены `uart: true` и `udev: true`: в контейнер попадают последовательные устройства хоста, в том числе узлы, на которые указывают `/dev/serial/by-id/*`. Дополнительно перечислены типовые пути (`/dev/ttyUSB0`, `ttyACM0`, `ttyAMA0`, `ttyS0`). Если узла нет в момент старта, Supervisor его пропускает — из-за отсутствующего `/dev/ttyUSB0` дополнение не должно отказываться запускаться.

Список на главном экране строится из `/dev/serial/by-id/*` и `/dev/ttyUSB*`, остальные найденные tty тоже показываются. Архитектуры: `amd64`, `aarch64`, `armv7`. Образ по умолчанию — `python:3.12-alpine` (`ARG BUILD_FROM`). Сторонние Python-пакеты не используются: кадры Modbus, CRC и `termios` — свои, на стандартной библиотеке.

Поля экрана пишутся в `/data/settings.json` и переживают перезапуск. Значения во вкладке «Конфигурация» — только первый запуск, пока этого файла нет.

## Согласование с интеграцией modbus

Запрос уходит на Supervisor API (нужен `homeassistant_api: true` и `SUPERVISOR_TOKEN`):

```http
POST http://supervisor/core/api/services/modbus/stop
Authorization: Bearer <SUPERVISOR_TOKEN>
Content-Type: application/json

{"hub": "<имя хаба>"}
```

После операции вызывается `modbus.reload` без имени хаба. Службу `modbus.restart` убрали в Home Assistant 2024.11, поэтому дополнение её не вызывает. Reload перечитывает YAML и заново открывает все хабы modbus.

Пока имя хаба пустое, операции запрещены. Галочка «HA не использует этот порт» снимает запрет и не трогает службы.

Кнопка «Освободить хаб» включает сессию: хаб остановлен, и следующие операции не вызывают stop/reload. «Вернуть хаб» делает reload и возвращает автоматический режим. В автоматическом режиме stop и reload идут на каждую операцию. Одновременные запросы не накладывают stop и reload друг на друга: счётчик операций под общим замком, reload делает тот, кто завершил последнюю.

Между операциями файловый дескриптор закрывается, перед `close` снимается `TIOCEXCL` (`TIOCNXCL`). Пока идёт скан, другие действия с шиной отклоняются. Все обращения к порту идут под одним замком.

## Кадр RTU

Кадр: адрес, функция, данные, CRC16 Modbus (младший байт первым). Конец кадра — тишина. При паузе `0` берётся максимум из 3.5 времени символа и 15 мс: у USB-RS485 пауза между кусками одного кадра часто длиннее спецификации, и короткий таймаут разрезает ответ.

Локальное эхо — это байты, совпадающие с отправленным кадром, а не просто быстрый ответ другого вида:

- ответ на чтение никогда не совпадает с запросом, поэтому одна копия запроса — это эхо;
- ответ на запись FC05/06/15/16 повторяет запрос. Одна копия считается эхом адаптера, только если она пришла быстрее порога (по умолчанию 5 мс); более поздняя — ответом устройства; две копии — эхо плюс ответ;
- буфер, который не равен запросу, эхом не считается, даже если пришёл сразу;
- порог `0` отключает проверку по времени для одиночной копии записи.

Запись на адрес 0 не ждёт полный таймаут: пауза короткая, в журнале будет «отправлено (broadcast, ответ не ожидается)», а принятые байты всё равно показываются. Сырой HEX с функцией не 01–04 или с адресом 0 сначала попадает в подтверждение, как обычная запись.

Если после эха остались байты без верного CRC, они показываются как есть. Так бывает с ответом на broadcast: многие платы реле отвечают кривым кадром. Это не ошибка программы.

Скан не отправляет функции записи. На каждый адрес, для каждой отмеченной скорости и чётности, пока нет годного ответа: отмеченные из FC03 (регистр 0, количество 1), FC01 и FC02 (количество 8). Кадр с верным CRC и адресом устройства считается попаданием, в том числе исключение (функция с установленным старшим битом). Если ответа нет, запрос повторяется столько раз, сколько стоит в поле «Повторы».

## Профили

### Eletechsup N4DSA02

| Регистр | Смысл | Доступ |
| --- | --- | --- |
| 0, 1 | температура, int16 × 0.1 °C; 32768 — датчика нет | чтение FC03 |
| 2 | адрес slave | чтение FC03, запись FC06 |
| 3 | код скорости: 0=1200, 1=2400, 2=4800, 3=9600, 4=19200 | чтение FC03, запись FC06 |

Новая скорость начинает работать только после снятия питания. Значение **5** в регистр 3 — заводской сброс; кнопки профиля такой кадр не готовят. Регистр **255** к скорости не относится, в профиле его нет. Сырой HEX это ограничение не проверяет: им можно послать что угодно, включая сброс.

### Реле 2CH/4CH (Bestep / LC и похожие)

Заводские параметры: адрес **255**, **9600 8N1**.

- реле — катушки 0…7, FC05: включить `0xFF00`, выключить `0x0000`; читать FC01 с адреса 0, количество **8**;
- входы — FC02 с адреса 0, количество **8**. Количество 4 на этих платах часто заканчивается таймаутом;
- новый адрес — broadcast на slave 0, FC16, регистр `0x0000`, одно значение. Для адреса 20 кадр без CRC: `00 10 00 00 00 01 02 00 14`;
- прочитать адрес — broadcast `00 03 00 00 00 01 85 DB`. Ответ может быть без CRC;
- скорость — FC16, регистр `0x03E9` (1001): 2=4800, 3=9600, 4=19200;
- таймер, пары «режим / время»: канал 1 — `0x0003` / `0x0004`, канал 2 — `0x0008` / `0x0009`, канал 3 — `0x000D` / `0x000E`, канал 4 — `0x0012` / `0x0013`. Режим `0x02` — автовключение по истечении времени, `0x04` — автовыключение. Время в шагах по 100 мс.

Во фрагменте YAML число реле и входов берётся из выбора 2, 4 или 8 каналов, чтобы не плодить мёртвые сущности. Входы одного канала-группы читаются одним `binary_sensor` с `slave_count` на единицу меньше числа каналов. У выключателей `command_on: 1` / `command_off: 0`: интеграция сама переводит это в `0xFF00` / `0x0000`.

### R4DCB08

Holding-регистры 0…7 — температуры int16 × 0.1 °C. Адрес slave у разных плат разный, его нужно взять со сканера.

## Фрагмент YAML

Вкладка YAML по умолчанию отдаёт только списки `sensors`, `switches` и `binary_sensors` — их вставляют в уже описанный хаб или в include. Галочка «Полный блок хаба» добавляет `modbus:` с портом, скоростью, чётностью и стоп-битами. Дополнение конфигурацию HA не переписывает. После вставки вызовите `modbus.reload` (кнопка «Вернуть хаб») и не держите порт открытым в этот момент.

У температур N4DSA02 в фрагменте стоит `nan_value: 32768`, чтобы отсутствие датчика было состоянием `unknown`, а не −3276.8 °C.

## Ограничения

- Только Modbus RTU, один последовательный порт. Биты данных 5…8, для этих плат нужно 8. ASCII и Modbus TCP нет.
- Скан пустой шины долгий: на каждый адрес до трёх таймаутов. Сузьте диапазон или уменьшите таймаут, если устройств мало.
- Очень быстрый ответ на запись (быстрее порога эха) можно принять за эхо адаптера. Если адаптер эхо не делает, поставьте порог 0.
- `modbus.reload` после операции поднимает все хабы modbus, не только указанный.
- Если имя хаба пустое, дополнение порт у интеграции само не забирает. Закройте хаб вручную, иначе порт будет занят.
- Запись значения 5 в регистр скорости N4DSA02 блокируют только действия профиля. HEX-вкладка отправит любой кадр.
- Ответ broadcast лучше читать глазами в журнале: CRC может не сойтись, и это ещё не значит, что плата проигнорировала запись.
- Фрагмент YAML для входов реле рассчитывает на чтение пачкой по 8. Одиночные опросы по одному биту на части плат молчат.
